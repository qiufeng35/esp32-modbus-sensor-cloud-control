## 一、本任务在底座上补的 4 处

底座（表 / 排程 / 判离线 / 恢复）原样沿用 2.3，但有 4 处必须补 —— 都是实机跑出来的真问题。

### ① platformio.ini 缺 4 行 USB 配置（★ 现象最像板子坏了）

**现象**：烧录 SUCCESS，但串口**一个字都看不到**；用脚本往串口写还会超时。
**根因**：少了下面这几行，Serial 打印走 UART0（IO43/44），而你插的是原生 USB 口 ——
两个口不是一回事，所以主机侧什么都没有。

`ini
build_flags =
    -Iinclude
    -DBOARD_HAS_PSRAM
    -DARDUINO_USB_MODE=1
    -DARDUINO_USB_CDC_ON_BOOT=1
`

**验证**：补上后同一个固件立刻正常输出。这一条与任务 2.1~2.3 的 platformio.ini 保持一致。

### ② 配置自检误报：主题名带下划线被判非法

**现象**：开机自检报「第 6 行有问题」，可这一行照说明书填的，没错。
**根因**：User_ConfigCheck() 校验主题名时只允许字母数字，而表里
humi5_0004 / 	emp5_0004 带下划线（同一台设备两个量要靠它区分）。
**改法**：自检放开下划线。

### ③ 	ime 的「完整轮次」永远是 0

**现象**：	ime 里「完整轮次 0」「上一轮 0 ms」「最长一轮 0 ms」，统计形同虚设。
**根因**：原判据是「这一圈没有任何一行到点」才算一轮结束。
可表里周期最短的是 1000 ms，而一轮 5 次事务本身就要约 1050 ms ——
**永远有某一行到点，这个条件永远不成立**。
**改法**：改成「表里每个量都刷新过一遍」记一轮（s_fresh 计数）。
实测修复后：事务 51 次 ｜ 完整轮次 8 ｜ 上一轮 5488 ms ｜ 最长一轮 6954 ms。

### ④ 	ime 的最坏耗时算错了一半

**现象**：	ime 说「全掉线最坏约 3300 ms」，实测要 10 秒以上。
**根因**：库的应答超时是**写死的 2000 ms**，原来按 500 ms 估算。
**改法**：按 2000 ms 重算（本工程 5 次事务 → 10800 ms），并注明掉线后
不再按周期探、而是每 2000 ms 探一次，稳态下不会次次等满 2 秒。

## 二、底座里唯一一处结构性补充：发帧入口收敛

src/02_business/src/task_sensor.cpp 新增：

`cpp
uint8_t Sensor_BusRead(uint8_t slave, uint8_t reg_type, uint16_t addr, uint16_t qty,
                       uint16_t* out) {
    uint32_t gap_us = SENSOR_BUS_GAP_MS * 1000UL;
    uint32_t used   = (uint32_t)(micros() - s_last_bus_us);
    if (used < gap_us) delayMicroseconds(gap_us - used);
    s_txn++;
    uint8_t err = Modbus_ReadRegs(slave, reg_type, addr, qty, out);
    s_last_bus_us = micros();
    s_busy = 0;
    return err;
}
`

自动轮读 / 命令台现场读 / 标定三处**全部改走它**。
**为什么要唯一**：原来命令台那一处直接调 Modbus_ReadRegs()，绕过总线间隙，
能紧贴着自动轮读发帧（等于对同一从站背靠背连发两帧），从站会漏答。
2.3 调测时实测：绕过守门人的那一处，约三分之一的读失败。

另外 src/03_protocol/src/modbus_rtu.cpp 补了 Response_Rebuild()：
库只保存寄存器值，不保存原始字节，所以 [收] 那句要把寄存器值按协议反拼回标准应答帧。
