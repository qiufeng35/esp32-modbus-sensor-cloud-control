# T31_WiFi —— 项目3 任务1 连上 WiFi：在 Modbus 底座上加网络【★ 直设版·库版】

> 注：本文是项目开发过程记录。文中真实热点名、内网 IP、MAC 与私钥均已替换为占位符；
> 当前版本的密钥配置方式见根目录 README「密钥加密」。


> **本册的一句话边界**：只办「网络身份证」——连上 WiFi、拿到一个 IP 地址。
> **不发数据**（发数据是任务 3.2 的事）。
>
> **本册最想让学员看到的一件事**：`loop()` 里并排住着两个「慢动作」——
> `WIFI_Loop()` 可能要等十几秒才连上，`Sensor_Loop()` 一笔 Modbus 事务最长等 2 秒；
> 两个都不许用 `delay` 等对方，各推各的状态机，谁都不按谁。
> **这就是「加网络没把总线读坏」的写法。**

## 7. 非阻塞状态机：本册的技术核心

### 7.1 为什么必须非阻塞

`WiFi.begin(ssid, pass)` **是「发出去就回来」的** —— 它只提交请求，不等人连上。
从提交到拿到 IP，可能要几百毫秒，也可能是十几秒（密码错、信号弱、路由器慢）。

如果在这里死等（`while (WiFi.status() != WL_CONNECTED) delay(500);`），后果是：
**整个程序被按住十几秒** —— 传感器不读了、命令不回了、心跳停了。

所以连接过程做成**状态机**，每次 `loop()` 只推一小步：

```cpp
void WIFI_Loop(void) {
    // ---- 已连上：只报「掉线」这一次状态变化 ----
    if (s_state == WIFI_ST_CONNECTED) {
        if (!WiFi.isConnected()) { ...自动重连... }
        return;
    }
    // ---- 连接中 / 有问题：每 500 ms 推进一次，绝不忙等 ----
    if (s_state == WIFI_ST_CONNECTING || s_state == WIFI_ST_TIMEOUT) {
        if ((uint32_t)(now - s_last_ms) < 500) return;   // ★ 没到点就立刻返回
        s_last_ms = now;
        if (WiFi.isConnected()) { s_state = WIFI_ST_CONNECTED; ...打印 IP... return; }
        ReportLibStatus(WiFi.status());                   // 状态变了才打印
        if (首连超时 10 秒) RestartConnect("首次连接超时");  // 转后台重试
    }
}
```

### 7.2 两个状态机并排

```cpp
void loop() {
    WIFI_Loop();      // ① 推进 WiFi 连接状态机（每次只走一小步）
    Sensor_Loop();    // ② 推进传感器轮询（非阻塞，一次最多一次事务）
    Console_Poll();   // ③ 命令台
    RS485_Loop();     // ④ 总线收字节
    ...心跳...
}
```

两个慢动作谁都不 `delay` 等对方 —— 这就是「加网络没把总线读坏」的写法。

### 7.3 超时与重试

| 宏 | 值 | 含义 |
|---|---|---|
| `WIFI_CONNECT_TIMEOUT_MS` | 10000 | 首次连接等 10 秒；超时**不等了**，转后台重试 |
| `WIFI_RETRY_MS` | 5000 | 后台每 5 秒重新提交一次连接请求 |
| `WIFI_SCAN_MAX` | 20 | 扫描结果最多列 20 个（防刷屏） |

### 7.4 状态翻译（本册最值钱的一张表）

库只给你一个数字，这张表告诉你「该去查哪儿」：

| 库的状态码 | 数值 | 中文解释 |
|---|---|---|
| `WL_IDLE_STATUS` | 0 | 空闲（等待下一次尝试） |
| `WL_NO_SSID_AVAIL` | 1 | ★ 搜不到这个名字 —— 名字写错，或它不是 2.4G 热点 |
| `WL_CONNECT_FAILED` | 4 | ★ 连不上 —— 多半是密码错，或路由器不让新设备接入 |
| `WL_CONNECTION_LOST` | 5 | 连接中断（路由器重启 / 信号太弱） |
| `WL_DISCONNECTED` | 6 | 已断开，正在重试 |
| `WL_SCAN_COMPLETED` | — | 扫描完成 |

## 10. 踩过的坑（值得知道）

### 10.1 编译目录为什么放到工程外面

本工程路径含中文（`…\项目2_库版\…`）。PlatformIO 会为链接器生成一个**响应文件**
（把上百个参数写进 `tmp*.tmp` 再交给 `ld.exe`），而链接器 `-Map` 参数写的是**绝对路径**。
在「含中文的绝对路径 ＋ 新增了 ArduinoMqttClient 这类库」的组合下，实测会出现：

```
ld.exe: cannot open map file …\firmware.map: No such file or directory
```

（**源文件都能编过、库也能链上，只有 map 写不出来** —— 命令行编码的坑。）

把编译输出目录指到一个**纯英文路径**就彻底绕开了，编译结果与默认完全一致：

```ini
[platformio]
build_dir = D:/pio_build/T31_WiFi
```

### 10.2 本任务在底座上补的 4 处（★ 每一处都是实机踩出来的）

底座整体沿用任务 2.3，但有 4 个地方必须补 —— 它们不是"顺手美化"，
而是换到项目3 的新环境以后，真机上跑出来的问题：

| # | 现象（实机） | 根因 | 改法 |
|---|---|---|---|
| ① | 串口**一个字都看不到**，板子像死了；主机往串口写还超时 | `platformio.ini` 少了 USB 相关那 4 行，串口打印走了 UART0（IO43/44），而你插的是**原生 USB 口** | 补 `build_flags`：`BOARD_HAS_PSRAM` / `ARDUINO_USB_MODE=1` / `ARDUINO_USB_CDC_ON_BOOT=1` |
| ② | 开机自检报「第 6 行有问题」，可这一行明明是对的 | 主题名 `humi5_0004` 带下划线，而自检只允许字母数字 | 自检放开下划线（同一台设备两个量要能区分） |
| ③ | `time` 里「完整轮次」永远是 0、「上一轮 / 最长一轮」永远是 0 ms | 原判据是"这一圈没有任何一行到点"；可周期最短 1000 ms、一轮事务就要约 1050 ms，**这个条件永远不成立** | 改成"表里每个量都刷新过一遍"算一轮 |
| ④ | `time` 说"全掉线最坏约 3300 ms"，实测要 10 秒以上 | 库的应答超时是**写死的 2000 ms**，原来按 500 ms 估算 | 按 2000 ms 重算（本工程实测 10800 ms），并注明掉线后改为每 2000 ms 探一次 |

> ★ 这 4 条对应四类通用教训：
> ① 配置缺一行，现象却像硬件坏了 → **先怀疑配置**；
> ② 自检自己报错，不一定是数据错 → **判据别写太严**；
> ③ 统计指标要能被触发 → **触发不了的统计等于没有**；
> ④ 估算法要按真实超时算 → **差一个数量级的估算比不估算更误导**。

另外，底座里唯一一处"结构性"补充是**发帧入口收敛**：
`task_sensor.cpp` 新增 `Sensor_BusRead()`，自动轮读 / 命令台现场读 / 标定
三处全部走它，发帧前统一等总线间隙。原来的写法在命令台现场读那一处会绕过间隙，
和自动轮读"背靠背"发帧，实测约三分之一的读会失败。

### 10.3 其它

| 现象 | 原因 | 处理 |
|---|---|---|
| 开机 10 秒不动就以为卡死 | 其实已经转后台重试了，看日志那一行 | 敲 `sensor` 验证：总线照常读 |
| `wifiscan` 卡 2~4 秒 | 13 个信道挨个听，正常 | 知道即可；这是唯一允许的阻塞例外 |

| ESP32 搜不到自家 WiFi | 那是 **5G** 热点 | 路由器里开一个 2.4G 的，或开手机热点 |
| ★ 串口一个字都看不到、板子像死了 | `platformio.ini` 少了 USB 那 4 行，打印没走原生 USB | 见 10.2 节第 ① 条；先查配置，别急着判硬件坏 |
| `static const char* s_ssid = NULL;` 为什么存的是 NULL | 它存的是**地址**，不是账号密码本身 | 账号密码在 `User_Config.h` 两个宏里；`const` 保护的是被指向的字符，不是指针；`static` 把名字限制在本文件可见 |
