> **ESP32-S3 × RS485/Modbus RTU × 巴法云 MQTT**：7 路 Modbus 传感器数据采集上云，云端主题反向控制继电器与采集总开关。

> 仓库中**不含任何明文密钥**：WiFi 账号密码与巴法云 32 位私钥在构建期加密进固件，详见 [「密钥加密」](#七密钥加密重点)。

## 一、项目简介

本项目是一个完整的物联网闭环示例：**Modbus RTU 采集 → ESP32 处理 → MQTT 上云 → 云端下发控制 Modbus 设备**。

- **上行**：ESP32-S3 作为 Modbus RTU 主站，轮询 RS485 总线上的 5 个从站（7 路物理量），
  按各自的巴法云主题发布到云端，手机 App / 小程序可直接看到数值卡片。
- **下行**：云端主题收到 `on` / `off` 后，ESP32 写从站 7 的线圈 1 控制继电器；
  另一个开关主题用于暂停 / 恢复传感器采集。
- **工程目标**：在同一个 `loop()` 里并行推进「WiFi 连接状态机」「Modbus 轮询」「MQTT 心跳」，
  全程非阻塞，加网络不会把总线读坏。

## 二、功能特性

| 能力 | 说明 |
|------|------|
| 7 路传感器采集 | 风速、风向、温湿度（两套）、光照，从站 1~5，配置表驱动，加一行即接新设备 |
| Modbus RTU 主站 | 9600 8N1，功能码 0x03 / 0x04 读寄存器，0x05 写线圈；200 ms 总线间隙守卫 |
| 云端上行为主 | 每 10 秒把整张表发布一遍；**读不到就跳过，不补旧值、不发假数据** |
| 云端下行控制 | `switch0006` 控继电器，`sensor0006` 控采集总开关，执行成功才回发状态 |
| 非阻塞 | WiFi 状态机、传感器轮询、MQTT 心跳同 loop，互不阻塞，掉线自动重连 |
| 断线自愈 | 每次重连后自动重新订阅控制主题，避免「断一次线云端就再也控不动」 |
| 串口命令台 | 11 条命令：查表、标定、改周期、看云端、立刻发布、本地开关继电器等 |
| 密钥加密 | 构建期 AES-128-CBC 加密，运行期 mbedTLS 解密；仓库零明文密钥 |

## 四、硬件与接线

| 项目 | 型号 / 参数 |
|------|-------------|
| 主控 | ESP32-S3-WROOM-1 **N16R8**（16 MB Flash + 8 MB Octal PSRAM），开发板 `esp32-s3-devkitc-1` |
| 总线 | RS485 模块（自动收发切换，无需 DE/RE 引脚），9600 8N1 |
| 接线 | RS485 RX = **IO18**，TX = **IO17**；调试串口走原生 USB，115200 |
| 从站 1~5 | 风速 / 风向 / 温湿度变送器 / 光照 / 探头式温湿度变送器（出厂默认地址 1、9600、N.8.1） |
| 从站 7 | Modbus 继电器模块，线圈 1 控制开关（本项目配置为反相，可在 `User_Config.h` 改） |
| 网络 | 一个 **2.4G** WiFi（ESP32-S3 不支持 5G 热点） |

> RS485 模块自带方向切换，因此代码里没有 DE/RE 控制；若你的模块需要手动切换方向，
> 需在 `04_driver` 层补充。

```
esp32-modbus-sensor-cloud-control/
├── platformio.ini              PlatformIO 工程配置（含构建期密钥钩子）
├── secrets.example.ini         密钥配置模板（复制为 secrets.ini 后填写）
├── src/
│   ├── main.cpp                上云与云端控制逻辑
│   ├── 01_user/                配置表 + 串口命令台
│   ├── 02_business/            传感器轮询 / 判离线 / 恢复
│   ├── 03_protocol/            Modbus RTU 协议层
│   ├── 04_driver/              UART / RS485 / WiFi 状态机
│   └── 05_secrets/             ★ 加密凭据解密（构建产物 + 运行时）
├── tools/
│   ├── aes128.py               纯 Python AES-128-CBC（构建期加密）
│   ├── gen_secrets.py          secrets.ini → 加密头文件
│   └── pio_secrets.py          PlatformIO 构建前钩子
├── lib/                        随工程携带的第三方库（离线可编译）
├── docs/                       开发过程记录（已脱敏）
└── .gitignore                  构建产物与本地密钥均不提交
```

`loop()` 的四步（谁都不 `delay` 等对方）：

```cpp
void loop() {
    WIFI_Loop();      // ① 推进 WiFi 状态机（掉线自动重连）
    Bemfa_Task();     // ② 连 MQTT、维持心跳、到点发布、处理云端下行
    Sensor_Loop();    // ③ 推进 Modbus 轮询（一次最多一个事务）
    Console_Poll();   // ④ 收串口命令
}
```

关键参数：发布周期 10 s，MQTT 心跳 60 s，重连间隔 15 s，总线间隙 200 ms，
连续失败 3 次判离线，离线设备每 2000 ms 探测一次。

## 六、快速开始

### 1. 准备环境

- [PlatformIO](https://platformio.org/)（VSCode 插件或 CLI 均可）
- 平台包：`espressif32`（本项目在 PlatformIO Core 6.2.0 + espressif32 7.1.3 +
  Arduino 核心 2.0.17 上实测编译通过）

### 2. 克隆仓库

```bash
git clone https://github.com/qiufeng35/esp32-modbus-sensor-cloud-control.git
cd esp32-modbus-sensor-cloud-control
```

### 3. 配置本地密钥

```bash
# Windows
copy secrets.example.ini secrets.ini
# macOS / Linux
cp secrets.example.ini secrets.ini
```

打开 `secrets.ini`，填写 `passphrase`、`wifi_ssid`、`wifi_password`、`bemfa_uid` 四项。
**这个文件只留在本地，已在 `.gitignore` 中，不会被提交。**

> 不创建 `secrets.ini` 也能编译：工程会进入「演示模式」，烧录后串口提示未配置，
> 但不连接 WiFi 与巴法云，方便先验证编译和板子是否正常。

### 4. 编译与烧录

```bash
pio run                 # 编译（构建前会自动加密 secrets.ini）
pio run -t upload       # 烧录
pio device monitor -b 115200   # 查看串口
```

### 5. 在巴法云创建主题

登录巴法云控制台，按 [「云端主题与控制」](#八云端主题与控制) 表格创建 7 个传感器主题
和 2 个控制主题（主题名必须与配置表逐字一致，只允许字母和数字，末尾三位是设备类型码）。

## 七、密钥加密（重点）

### 7.1 解决什么问题

源码里一旦出现 WiFi 密码或巴法云私钥，就会随仓库、截图、压缩包一起泄漏。
本项目把凭据从源码中彻底移出，改由构建期加密、运行期解密：

```
secrets.ini（本地明文，gitignore）
        │
        │  tools/gen_secrets.py
        │  PBKDF2-HMAC-SHA256(passphrase, salt, 20000) → 128 位密钥
        │  AES-128-CBC + PKCS#7 加密
        ▼
src/05_secrets/gen/secret_blob.h（密文 + IV + 密钥材料，gitignore）
        │
        │  编译进固件
        ▼
ESP32 启动：mbedTLS AES-128-CBC 解密 → 只在内存中还原 → 不打印内容
```

### 7.2 文件职责

| 文件 | 是否提交 | 作用 |
|------|:---:|------|
| `secrets.example.ini` | ✅ | 模板，只有占位符 |
| `secrets.ini` | ❌ | 本地真实凭据（已 gitignore，**永远不要提交**） |
| `tools/gen_secrets.py` | ✅ | 读取 ini、加密、生成头文件；无 ini 时生成演示模式 |
| `tools/aes128.py` | ✅ | 纯 Python 的 AES-128-CBC 实现（无第三方依赖） |
| `tools/pio_secrets.py` | ✅ | PlatformIO 构建前自动调用生成脚本 |
| `src/05_secrets/gen/secret_blob.h` | ❌ | 构建产物（密文与密钥材料，已 gitignore） |
| `src/05_secrets/src/secret_store.cpp` | ✅ | 运行期用 mbedTLS 解密并解析 |

### 7.3 手动验证加密链路

```bash
# 生成/更新加密头文件（正常编译会自动执行，这里仅演示）
python tools/gen_secrets.py

# 校验纯 Python AES 实现是否符合 FIPS-197 / NIST SP 800-38A 标准向量
python tools/aes128.py
```

> Windows 上若没有 `python` 命令，把上面的 `python` 换成 `py -3` 即可。
> `secrets.ini` 请保存为 UTF-8 编码。

### 7.4 安全边界（务必了解）

这层加密的目标是**避免凭据以明文出现在仓库、源码与日志里**，它有两个明确边界：

1. 解密所需的密钥材料最终在固件中，能读出固件的人理论上可以还原凭据；
2. 它不能替代真正的设备安全方案。

生产环境建议叠加：**ESP32 Flash 加密 + NVS 加密 + 每台设备独立凭据**，
或改用一机一密的云端下发机制。本项目定位是课程 / 学习示例。

## 八、云端主题与控制

### 8.1 上行主题（7 个，末尾 `0004` = 传感器类型码）

| # | 主题 | 物理量 | 从站 | 功能码 | 寄存器 | 格式 | 系数 | 单位 |
|---|------|--------|:---:|:---:|:---:|:---:|:---:|:---:|
| 1 | `reg0004` | 风速 | 1 | 0x03 | 0x0000 | U16 | 0.1 | m/s |
| 2 | `dir0004` | 风向 | 2 | 0x03 | 0x0001 | U16 | 1.0 | deg |
| 3 | `humi0004` | 湿度 | 3 | 0x03 | 0x0000 | U16 | 0.1 | %RH |
| 4 | `temp0004` | 温度 | 3 | 0x03 | 0x0001 | S16 | 0.1 | ℃ |
| 5 | `lux0004` | 光照 | 4 | 0x03 | 0x0008 | U16 | 1.0 | lux |
| 6 | `humi50004` | 湿度5 | 5 | 0x03 | 0x0000 | U16 | 0.1 | %RH |
| 7 | `temp50004` | 温度5 | 5 | 0x03 | 0x0001 | S16 | 0.1 | ℃ |

> 巴法云主题名只允许字母和数字：不能带下划线、空格、中文。
> 同一台设备的两个量用「名字 + 序号」区分，即 `humi50004` / `temp50004`。

### 8.2 下行控制主题（2 个，末尾 `0006` = 开关类型码）

| 主题 | 作用 | 消息 | 动作 |
|------|------|------|------|
| `switch0006` | 继电器开关 | `on` / `off` | 写从站 7 线圈 1；执行成功才回发状态 |
| `sensor0006` | 采集总开关 | `on` / `off` | `on` 恢复采集与上报；`off` 暂停读总线，云端保留最后值 |

云端下发是**白名单**处理：只认 `on` / `off`（兼容 `1` / `0`），其他内容一律忽略。

### 8.3 MQTT 连接参数

| 参数 | 值 |
|------|-----|
| 服务器 | `bemfa.com:9501`（普通端口；巴法云另有加密端口 9503，本项目未使用） |
| Client ID | 巴法云 32 位私钥（来自加密存储，不写在源码） |
| Keep Alive | 60 s（巴法云超过 65 s 判离线） |
| 发布周期 | 10 s |
| 重连间隔 | 15 s |

## 九、串口命令

波特率 115200，命令以回车结束：

| 命令 | 作用 |
|------|------|
| `help` | 显示全部命令 |
| `sensor` | 看整张配置表（配置 + 本次值 + 状态） |
| `sensor <行号>` | 看某一行，含原始值十六进制，便于核对说明书 |
| `cal <行号> <标准值>` | 标定；`cal <行号> 0` 清除零点修正 |
| `period <行号> <毫秒>` | 临时修改该路读取周期（掉电恢复表内值） |
| `time` | 排程体检：事务数、轮次、耗时 |
| `mqtt` | 云端状态：服务器 / WiFi / 连接 / 在线数 / 各主题当前值 |
| `pub` | 立刻把整张表发布一遍，并逐行说明「已发 / 跳过」 |
| `relay [on\|off]` | 本地直接开关继电器（不经过云），用于验总线与反相 |
| `enable [on\|off]` | 本地暂停 / 恢复采集 |
| `wifi` | WiFi 状态：IP / 网关 / DNS / 信号 / MAC |

### 10.1 配置了 secrets.ini（正常模式）

```
UART0(USB) 就绪
```

```
[密钥] ★ 演示模式：未配置 secrets.ini，WiFi 与巴法云私钥为空

[WiFi] ★ 已跳过连接：按 README 创建 secrets.ini 后重新编译
```

## 十一、常见问题排查

| 现象 | 原因 | 处理 |
|------|------|------|
| `[密钥] ★ 解密失败` | `passphrase` 与生成密文时不一致，或 `secret_blob.h` 残留 | 确认 `secrets.ini` 后重新编译（必要时删 `src/05_secrets/gen/` 再编译） |
| 编译时提示 secrets.ini 还是示例内容 | 直接复制模板未修改 | 填入真实 WiFi 与私钥，或删除 `secrets.ini` 用演示模式 |
| `已上传 0/7 在线 0/7` | 一路传感器都没读到：没接线 / 没供电 / A-B 反 / 从站地址或波特率不对 | 敲 `sensor` 看状态，先查 RS485 总线，与 WiFi 无关 |
| 一直「未授权（库码 5）」 | 巴法云私钥不对 | 到巴法云「连接密钥」页核对 `bemfa_uid` |
| 连上云端但手机没有数据 | 主题没建或名字不一致 | 逐字核对 7 个上行主题 |
| 连上约两分钟就掉线 | 心跳设置过大 | 本项目 60 s，巴法云 65 s 判离线 |
| 云端下发没反应 | 订阅没随重连恢复 | 本项目在连接成功分支里重新订阅；若自行修改请保持该结构 |
| 串口一个字都看不到 | 板子插的是原生 USB，但 `platformio.ini` 少了 USB 配置 | 保留 `ARDUINO_USB_MODE=1` 与 `ARDUINO_USB_CDC_ON_BOOT=1` |
| WiFi 搜不到自家热点 | ESP32-S3 只认 2.4G | 路由器开 2.4G，或用手机热点 |
| `pio run` 提示找不到 `secret_blob.h` | 手动改了构建流程 | 直接用 `pio run`，构建前钩子会自动生成该文件 |

## 十二、隐私与安全说明

本项目对隐私信息做了两层处理：

1. **凭据加密（发布版零明文）**
   - 仓库中不存在真实 WiFi 账号密码与巴法云私钥；
   - 真实值只存在于本地 `secrets.ini`，构建时加密、运行期解密；
   - 生成物 `src/05_secrets/gen/` 与 `secrets.ini` 均在 `.gitignore` 中。

2. **文档脱敏**
   - `docs/` 下的开发记录中，真实热点名、内网 IP、MAC 地址、私钥片段
     全部替换为占位符（如 `192.168.x.x`、`你的2.4G热点`）。

**你需要自己注意的**：

- 不要提交 `secrets.ini`、不要把它截图发到群里或上传网盘；
- 如果曾把真实凭据提交到公开仓库，请立即在巴法云与路由器上更换密码 / 私钥；
- 加密口令 `passphrase` 请自行保存，丢失后需重新填写并重新编译。
